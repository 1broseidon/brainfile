# TUI v3.1 — Hierarchy, Type Views, Detail v2 (binding spec)

Decisions locked (George, 2026-08-12): flat cursor · expanded by default · type-cycle for views. Scope is the TUI view layer only. Builder: follow this exactly; record any forced deviation with justification.

## Part A — List view

### A1. Collapse/expand (spacebar)
- `space` on a row whose document has visible children (any doc with children via `parentId` rendered under it) toggles collapse. On rows without children: no-op.
- Glyph communicates state for parents-with-children: `▾` expanded, `▸` collapsed. (Epics without children keep the static `▸` type glyph as today — the rotation only applies when children exist. If this creates ambiguity for childless epics, prefer: parents-with-children use `▾/▸`, all other rows keep their type glyph unchanged.)
- Collapsed row: first chip becomes `N hidden`, then the usual chip priority (contract state, subtask progress, tag), still capped at 3.
- **Default expanded.** Collapsed IDs persist in `.brainfile/state/tui.json` (new local state file; reuse the atomic-write helper from briefState; `state/` is already gitignored). Format: `{ "collapsed": ["epic-1", ...] }`. Survives restarts. Never touches board files.
- Counts in the column tabs are unaffected by collapse (collapse hides rows, not truth).

### A2. Type-cycle views (`t`)
- `t` cycles: all → task → epic → spec → plan → adr → all. Only include types that exist on the current board (from board config `types` + the default task), 'all' always present.
- Active type shown in the header line after the column tabs: ` · plan` (dim; omit for 'all').
- Composes with `/` filter (AND). Column tab counts reflect the type filter.
- Footer gains `t type` in list context. HelpOverlay updated.
- Children visibility under type filter: when filtering to a type, show matching docs flat (no orphan-parent indentation games — the `← parent` reference style already handles a visible child whose parent is filtered out).

## Part B — Detail v2

### B1. Anatomy (top to bottom, both wide-pane and narrow-fullscreen)
```
 epic-1 ▸ task-2   Prune supervisor remnants from docs        todo · med
 ─────────────────────────────────────────────────────────────────────
 #docs   assignee —   created 08-11   parent epic-1
 description                                                      ↕ 2/9
   docs/guides/orchestration.md still documents @brainfile/…
 children (3)
   task-1  Triage marketing board                     todo
 subtasks (0/2)
   ◻ sweep guides
 contract   ⧉ ready
   deliverables  docs/guides/orchestration.md — rewrite
   validation    npm test -w cli
 activity
   08-12 [claude] moved todo → in-progress
 files  docs/guides/orchestration.md
```
- Header: breadcrumb chain (`parent ▸ current`, grows with drill-down, truncate from the left with `…` when long), title, `column · priority` right-aligned.
- Meta row: tags, assignee, created, parent (id; if the parent doc's type is plan, render `plan plan-N`).
- Sections render only when non-empty (childless task shows no children header, etc.).
- Contract block is real: state word colored per v3 palette; deliverables (up to 3, `path — description`); validation commands (up to 2, dim); `feedback` in red tint when present (failed contracts).
- Activity: last 5 log entries, newest first, from the task body's Log section. Core's brief implementation already parses both historical log-line formats — **export that parser from core** (e.g. `parseLogEntries`) as the one additive core change permitted, rather than duplicating it in the TUI. If ledger records for this doc exist (readLedger), merge them in; absent ledger degrades silently (known task-11 gap).

### B2. Flat cursor (the locked decision)
- One cursor, j/k, moving through **selectable stops** top to bottom: each child row, then each subtask row. Description, contract, activity, files are landmarks, not stops.
- `space` toggles the subtask under the cursor (existing action wiring).
- `enter` on a child row drills into that child's detail; breadcrumb grows; `esc` pops one level; `esc` at the root detail returns to the list. Maintain a simple id stack.
- `p` jumps to the parent's detail when a parent exists (footer shows it conditionally).
- **Body scrolling is cursor-independent**: `u`/`d` scroll the description region by half its visible height regardless of cursor position; a dim `↕ n/m` indicator sits on the description header line when the body overflows. j/k never scroll the body — predictability over cleverness. The current behavior of silently truncating the body is removed.
- Footer (detail context): `↵ open child · space toggle · u/d scroll · p parent · e edit · m move · esc back` — items appear only when applicable (no `p` without parent, no `space` without subtasks, never `c complete` on non-completable types — existing rule).

## Constraints
- View layer only: changes confined to `cli/src/tui/**` + the single additive core export (`parseLogEntries` or equivalent) + `HelpOverlay`/footer content. No MCP, no commands, no board-file writes. `.brainfile/state/tui.json` is the only new write target.
- `actions.ts` signatures untouched.
- zod stays 4.3.6; typecheck stays seconds.
