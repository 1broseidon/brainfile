## Share a board without a service

Your board is still a folder of Markdown in `.brainfile/`, and your agents still read it directly. What's new: inside a git repository, that folder now lives on its own `brainfile` branch. Every change is a commit, your code branch and pull requests never see it, and you can share it through any git remote you choose.

**Nothing leaves your machine until you choose a remote.**

```bash
brainfile init                        # inside a repo: the board gets its own branch
brainfile where                       # where is my board, who has it, what's waiting to be sent
brainfile sync --set-remote origin    # share it (or a private repo URL)
```

After that, changes go out in the background a few seconds after each edit. A teammate who clones the repo gets the board the first time they run `brainfile`, with no setup. Anyone who never runs brainfile never sees the folder.

### What's in it

- **`brainfile where`** answers the question you'll have first: where the board is, how it's stored, who else has it, and whether anything is waiting to be sent. It never touches the network.
- **`brainfile sync`** fetches, merges and pushes the board branch, entirely inside `.brainfile/`. Point it at `origin` for a team board, or at a separate private repo when the board holds notes that shouldn't sit next to public code.
- **Automatic sharing.** Once a remote is set, edits from the CLI, the MCP tools and the TUI are sent in the background. `brief` pulls first. The TUI header tells you where you stand: `synced 12s ago`, `local only`, or `not synced · saved locally`.
- **Conflicts that resolve themselves.** Two agents moving the same task on two machines is a merge, not a problem. Fields merge one by one and the latest change wins, logs and notes combine, and completions are never lost. Anything genuinely ambiguous is left for a person, and `sync` names the file.
- **An audit trail for free.** Each change is one commit authored as the agent that made it, so `git -C .brainfile log` reads as the board's history.
- **`brainfile migrate --to-branch`** moves an existing board onto the branch. History comes along when the board was committed with your code, and uncommitted edits and new files always do. Every file is checked before the old copy is removed, and any failure rolls everything back. `--to-plain` reverses it.

### Upgrading

- **Existing boards are untouched.** Run `brainfile migrate --to-branch` when you want one on its own branch.
- **`brainfile init` inside a git repo now creates the branch-backed board** at the repository root. Pass `--plain` for a plain folder, as before.
- **Board discovery stops at the repository root.** A board kept in a directory above a repository is no longer picked up from inside it. Point at it with `-f <path>`.
- **The branch is hidden, not secret.** A plain `git push` never sends it, but `git push --all` and `--mirror` do. Once it's on a remote, anyone who can read that remote can read the board.
