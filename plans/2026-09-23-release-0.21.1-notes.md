## A shared board that stays out of your branches

0.21.0 shared the board by pushing it as a `brainfile` branch. That worked, but every background push made GitHub show "had recent pushes" with a Compare & pull request button, and the board sat in your branch list. 0.21.1 stores it where hosts don't look.

**On the remote, the board is now `refs/brainfile/board`, not a branch.** It is pushed, fetched and kept like any other git ref. GitHub and GitLab only list branches, so there is no banner, no pull request offer, and nothing in the branch list or `git branch -a`.

```bash
brainfile sync --set-remote origin
brainfile where     # shows the ref, and on GitHub a link to the board's history
```

### What's in it

- **Nothing to do for new boards.** `sync --set-remote` publishes to `refs/brainfile/board`. A teammate who clones the repo still gets the board on their first `brainfile` command: brainfile asks the remote once, never prompts for credentials, gives up after a few seconds, and remembers a miss for ten minutes.
- **The board on the web.** For GitHub remotes, `brainfile where` prints `https://github.com/<owner>/<repo>/commits/refs/brainfile/board`, the board's full history.
- **Who did what, without being told.** Board commits are now always authored by you. When an agent makes the change, the commit message ends with its name, like `move task-7: review [codex]`, and notes carry the same `[name]`. brainfile uses `--agent` or `BRAINFILE_AGENT` when given, otherwise it finds the nearest agent CLI above the command (claude, codex, cursor-agent, gemini, opencode and others), falling back to the variables agents set for their commands. Commands you type get no tag, and your notes carry your git `user.name`.
- **`--board-name`** replaces `--remote-branch` for keeping several boards in one private repository. The old flag and config key still work.

### Upgrading from 0.21.0

- **Boards shared as a branch move themselves.** The first `brainfile sync` merges the `brainfile` branch from the remote, publishes it under `refs/brainfile/`, and deletes the branch, but only if nobody pushed to it in the meantime.
- **Upgrade every machine that shares a board.** A machine still on 0.21.0 keeps pushing to the branch.
- **Scripts reading JSON:** `sync --json` and `where --json` report `remoteRef` instead of `remoteBranch`, and `where` adds `webUrl`.
- `git push --all` and `--mirror` still publish the board, because locally it is a branch. A plain `git push` never does.

### Install

```bash
npm i -g brainfile@0.21.1
```
