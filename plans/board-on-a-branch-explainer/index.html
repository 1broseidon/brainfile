Board on a branch

Today the board lives inside the code's working tree, so every worktree and every machine keeps its own stale copy. Spec-9 moves it to its own branch of the same repo: the same files, their own history, one copy shared by every worktree, synced through whatever remote you choose. Or none.

The same four situations, before and after

Pick a situation. Everything that doesn't take part in it fades out on both sides.

How it works, in five moves

01

Give the board its own branch

An orphan branch with unrelated history, checked out as a linked worktree at the path the board already uses. The CLI hides it from the code branch with an exclude entry, so no gitignore commit is needed.

git worktree add --orphan -b brainfile .brainfile
02

Commit every change, as the agent

Each add, move, note, or completion becomes one small commit. Agents never think about committing, and blame on a task file answers who wrote what.

move task-3: todo -> in-progress · author claude <claude@brainfile.local>
03

Share across worktrees for free

Every worktree of a repo shares one git directory, and a branch can only be checked out once. Any command from any worktree asks git where the board is and finds the same directory.

git worktree list --porcelain   # → the worktree on refs/heads/brainfile
04

Sync through the remote you choose

Fetch, merge without rewriting anyone's commits, push. Brief syncs before it reads. Offline works and catches up later. No remote is ever assumed, so a private board can sit next to public code.

brainfile sync --set-remote git@github.com:you/boards.git
05

Same trick outside a repo

In a plain folder the board is a standalone repo with the same commits and sync. A home board at ~/.brainfile is your system-wide todo, addressed with -g. Discovery stops at a repo's toplevel, so a project never silently writes into it.

brainfile init -g && brainfile sync -g --set-remote <private url>

Three places you'd use it

A

Repo with git

Cost: one command to adopt, none per day.

  • New project: init at the repo root creates the branch, the worktree, and the exclude entry.
  • Existing board: committed boards keep their history through a subtree split. Gitignored boards, like brainfile's own, import in one commit.
  • Orca worktrees: found through the worktree list. The TUI watcher already sees every agent's writes because it is one directory.
  • Second machine: board on origin, the clone already has it. Board on a private remote, one extra command.
B

Folder without git

Cost: zero unless you opt in.

  • Plain stays plain. Today's directory board keeps working with no warnings.
  • Opt in: the board directory becomes a standalone repo. Same commits, same sync to any remote.
  • Later becomes a repo: a local fetch folds the board's history in as the brainfile branch. Nothing lost.
C

Home board

Cost: one command per machine.

  • Create: brainfile init -g makes ~/.brainfile using the standalone machinery.
  • Address: -g on any command, an environment variable for agents, an MCP instance pinned to it for morning or scheduled agents.
  • Discovery: a repo without a board says so instead of writing into your personal todo. Outside any repo the home board is reachable and says so.
  • End state: one private boards repo with a branch per project plus home, and a web board served over it.

Checked in a scratch repo

Every mechanism the design depends on was run against real git 2.43 on 2026-09-21 before the spec was written.

  1. Orphan worktree inside the main tree, hidden by the exclude file. Outer status stays clean.
  2. A linked code worktree finds the board through the worktree list.
  3. Board pushed to a different remote than the code. Origin holds only main.
  4. Second machine: clone, add the board remote, fetch, create the worktree. Agent author names survive.
  5. Concurrent edits on two machines merge without rewriting history.
  6. A worktree inside the git directory is allowed, for bare-repo layouts.
  7. A standalone board repo in a plain folder pushes as its own branch of a shared boards remote.
  8. A standalone board folds into a later outer repo through a local-path fetch, history intact.
